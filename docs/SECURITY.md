# DevRelief — Security & Privacy Architecture

**Product:** DevRelief  
**Document:** Security Model, Threat Matrix & Privacy Architecture  
**Status:** v1.0.0 Production Release  

---

## 1. Security Philosophy & Threat Model

DevRelief operates on a Zero-Trust Ingestion standard: **Every uploaded file, extracted string, clipboard snippet, recipe template, and model response is treated as hostile, untrusted data.**

### Threat Vectors & Architectural Mitigations

| Threat Vector | Potential Impact | DevRelief Architectural Defense |
| :--- | :--- | :--- |
| **Executable Uploads** | Remote code execution on user or server host | Strict magic-byte file signature validation. Absolute rejection of `.exe`, `.dll`, `.so`, `.sh`, `.bat`, `.cmd`, `.py`, `.vbs`. |
| **Path Traversal Attacks** | Overwriting system files via filenames containing `../../` | Complete stripping of directory paths from filenames. Generation of ephemeral isolated UUID identifiers. |
| **Decompression / ZIP Bombs** | Resource exhaustion and disk/memory denial of service | Direct archive ingestion (`.zip`, `.tar.gz`, `.7z`) is blocked. Office documents (`.docx`, `.xlsx`) are unpacked under bounded byte and entry-count quotas. |
| **XML External Entity (XXE)** | Local file disclosure or SSRF via XML/Office documents | XML parsers explicitly disable `resolveExternals`, `loadDTD`, and external entity expansion. |
| **Prototype Pollution** | Hijacking application logic or RCE via malicious JSON imports | Strict checks in `RecipeStore`: JSON revivers and validation logic reject objects containing `__proto__`, `constructor`, or `prototype` keys. |
| **Server-Side Request Forgery (SSRF)** | Probing intranet services via configurable backend proxy endpoints | Endpoint parameters on `/api/ollama/tags` are parsed and validated strictly against `http:` and `https:` schemes, preventing file/gopher/arbitrary protocol access. |
| **Secret & Credential Leakage** | Accidentally sending AWS keys, JWTs, or passwords to models or logs | Automatic pre-processing regex redaction engine (`SecretScanner`) sweeps all extracted text before storage, transmission, or display. Recipes containing credentials are rejected pre-flight. |
| **Cross-Site Scripting (XSS)** | Malicious HTML/JS injected via rendered Markdown reports | All Markdown output rendered via secure React trees with strict DOMPurify sanitization. Script tags and `javascript:` URIs completely stripped. |
| **AI Command Auto-Execution** | Malicious shell commands generated by model executed on host | **Absolute architectural prohibition:** DevRelief never automatically executes commands, scripts, or network requests generated by an AI model. All suggestions are labeled unverified proposals and require manual user execution. |
| **Silent Cloud Exfiltration** | Sensitive code or data sent to external cloud APIs without user knowledge | Consent gate enforcement: Cloud provider calls are blocked with HTTP 403 unless `userConsent === true`. UI renders `CloudConsentModal` detailing exact payload and target model. |

## 2. Automated Secret & Credential Redaction Engine (`SecretScanner`)

Prior to rendering, persisting in history, or passing extracted text to any analysis engine, all content passes through `SecretScanner`:

```typescript
export const SECRET_REDACTION_RULES = [
  { name: 'AWS Access Key ID', pattern: /\b(?:A3T[A-Z0-9]|AKIA|AGPA|AIDA|AROA|AIPA|ANPA|ANVA|ASIA)[A-Z0-9]{16}\b/g },
  { name: 'AWS Secret Access Key Assignment', pattern: /(aws_secret_access_key\s*[:=]\s*["']?)([A-Za-z0-9/+=]{40})(["']?)/gi },
  { name: 'GitHub Personal Access Token', pattern: /\bgh[pousr]_[A-Za-z0-9_]{36,255}\b/g },
  { name: 'Bearer Token Header', pattern: /(Bearer\s+)[A-Za-z0-9\-._~+/]+=*/gi },
  { name: 'RSA / SSH Private Key Block', pattern: /-----BEGIN\s+(?:RSA|OPENSSH|DSA|EC)?\s*PRIVATE KEY-----[\s\S]*?-----END\s+(?:RSA|OPENSSH|DSA|EC)?\s*PRIVATE KEY-----/g },
  { name: 'Password / API Key Assignment', pattern: /((?:api_?key|auth_?token|client_?secret|db_?password|secret_?key|password)\s*[:=]\s*["'])([^"'\r\n\s]{8,})(["'])/gi },
];
```

## 3. Storage Privacy & Data Retention Policy

- **Isolated Browser-Origin Storage**: Recipes, execution history, and user settings are persisted strictly in the browser's namespaced local storage (`devrelief:*`).
- **Zero Third-Party Telemetry**: DevRelief contains zero analytics beacons, telemetry pings, tracking cookies, or diagnostic pings.
- **Configurable Retention Cap**: Execution history enforces a user-configurable maximum limit (default 50 entries, adjustable 5–500), automatically pruning the oldest entries to avoid storage bloat.
- **Immediate Data Purge**: Users can delete individual history records or clear the entire database at any time from the UI with zero remnants.
- **Export Scrubbing**: Exporting recipes or history generates clean, sanitized JSON with secrets pre-redacted.

## 4. Server Security Hardening (`server.ts`)

- **Security Response Headers**: Every server response includes:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: SAMEORIGIN`
  - `Referrer-Policy: strict-origin-when-cross-origin`
- **Body Payload Limit**: JSON body parsing is capped at 10 MB.
- **Prompt Size Guard**: Input prompts sent to `/api/gemini/generate` are capped at 500,000 characters.
- **Credential Isolation**: `GEMINI_API_KEY` is read strictly from backend environment variables and is never exposed in browser bundles, responses, or error traces. Error responses strip any query string credentials (`key=[REDACTED]`).
